# Развитие системы

Система пополняется из реальных презентаций. Примеры слайдов разбираются, и из них появляются новые компоненты, варианты и макеты.

## Цикл
1. **Пример.** Слайды (PDF, PPTX, скриншоты) попадают во входящие `inbox/<дата>-<тема>/` в репозитории.
2. **Разбор.** Отчёт `reviews/<дата>-<тема>.md`: каждый слайд сопоставлен с системой (есть готовое / нужен вариант / нужен новый компонент / не берём), проверены контраст, размер текста и печать.
3. **Решение.** Изменения из разбора согласуются до реализации.
4. **Реализация.** Новый компонент появляется со статусом «бета» и ссылкой на разбор. Версия системы повышается, запись добавляется в «Историю изменений».
5. **Стабилизация.** Бета-компонент, который хорошо показал себя в 2+ презентациях, становится стабильным.

## Статусы компонентов
Статус указан внизу описания каждого компонента.
- **Стабильный** — можно использовать без оглядки.
- **Бета** — API может поменяться в минорной версии.
- **Устаревший** — есть замена. Компонент удаляется в следующей мажорной версии.

## Что не попадает в систему
- Единичные решения под один слайд. Сначала их реализуют прямо в презентации, в систему они попадают при повторе.
- Приёмы, которые нарушают основы: текст мельче 24px, контраст ниже AA, тёмные, серые или сплошные цветные фоны на весь слайд или крупный блок, двойные оси, цвет без подписи.

## Выходные презентации
Готовые презентации лежат в `presentations/<дата>-<тема>/`: исходник `deck.jsx`, страница `index.html` и PDF. Каждая хранит копию системы той версии, на которой собрана (`lib/`), поэтому обновления системы старые презентации не ломают. Перейти на новую версию можно командой `--upgrade`.
